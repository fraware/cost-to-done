# Vision: the real economics of completed AI work

## The problem

AI is increasingly purchased to complete work, yet most pricing comparisons describe the price of computation. A quoted price per million tokens cannot establish the cost of a verified fix, a correct analysis, or a successful operation. Real workflows contain attempts that fail, tool calls, repeated context, verification, and human intervention. The relevant unit of economic value is the **accepted outcome**.

The measurement problem is scientific and operational. A model judged on a convenient benchmark does not necessarily generalize to a particular engineering repository. A model tested under one harness is not equivalent to that model under another. A pass is meaningful only relative to a defined verifier and an execution history that allows scrutiny. A dollar figure is meaningful only if its price basis is disclosed.

## The ambition

**Cost to Done aims to become the open standard for measuring the price of completed AI work.**

The product should eventually let a developer connect a repository, choose a task and acceptance conditions, select candidate model/agent configurations, set a budget, and execute a repeatable comparison. The outcome is a cost-to-completion frontier supported by complete receipts, not an unexplained rank. It should also allow organizations to replay cost assumptions against their own workloads while distinguishing statistical projections from measured evidence.

## First-class principles

1. **Completion is a verified event.** Clear task definitions, externally controlled tests, and preserved artifact identity.
2. **Failures are economic events.** Count aborted attempts, retries, tokens, tool costs, and time. State which cost categories were measured or omitted.
3. **Comparisons are conditional.** Distinguish model, harness, prompt, retry policy, provider route, execution environment, benchmark composition, and human involvement.
4. **Claims ship with receipts.** Publish reproducible task manifests, configuration pins, raw trials, verifier evidence, cost policy, and uncertainty. Avoid implied audit guarantees.
5. **Independent use precedes authority.** A developer running it against real work provides more evidence of utility than a beautifully rendered leaderboard.
6. **Surprising findings earn their headline.** Marketing cannot determine measured winners, run exclusion rules, or the treatment of missing data.
7. **Privacy is structural.** No default upload of private repositories, traces, prompts, or provider credentials.
8. **Open interfaces over monoliths.** Use battle-tested evaluators such as Harbor for agent execution. Invest in the economic record, reproducibility, and decision experience.

## Launch thesis

A launch timed to a major model release should reproduce a narrow, consequential claim on real end-to-end agent tasks. The resulting story should be understandable in seconds, with every detail one click away. The public artifact needs a repeatable command and a locally useful tool; the attention is a distribution channel, not the product.

**GitHub Trending #1 is an ambition for adoption**, not evidence of validity. No headline numbers will be manufactured to achieve it.

## Where this goes

Repository fixes are the first workload. The same framework eventually belongs in data transformations, scientific computation, research tasks, testing, enterprise operations, and tasks involving multiple tools or agents. Each workload needs its own acceptance contract and total-cost policy. Generalizing the format does not license generalizing a model ranking across unrelated work.

The enduring benchmark question is concise: *For this work, under these constraints, what does a verified completion actually cost?*
